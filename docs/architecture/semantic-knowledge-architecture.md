# Semantic knowledge architecture acceptance

The repository's current semantic authority is the immutable
[`regex-semantic-features-2026-09-08.v4.json`](../../semantic-corpus/snapshots/regex-semantic-features-2026-09-08.v4.json)
snapshot. Its declared cutoff is `2026-09-08T00:14:25Z`. The snapshot is
exhaustive only against the scope, sources, and adversarial methods bound by
the associated freeze manifest. It is not a claim of timeless completeness.

The machine-readable semantic foundation manifest and acceptance report bind
the frozen snapshot to its research ledgers, candidate dispositions, source
coverage, identity lock, derivation catalog, scientific-foundation acceptance,
and unchanged predecessor denominator. Run the acceptance check with:

```sh
python tools/semantics/certify_semantic_knowledge.py --check
```

## Authority boundaries

Semantic decisions have one owner:

| Question | Canonical owner |
| --- | --- |
| Which enduring entity does a feature record denote? | scientific identity architecture |
| What is the feature's canonical meaning? | current frozen semantic snapshot |
| What behavior belongs only to a semantic variant? | variant record |
| What spelling or API restriction belongs to a source surface? | manifestation record |
| What observable host action is being performed? | operation registry |
| What dimensions and vocabularies may be attributed? | facet model |
| Which publisher and scope support an assertion? | source registry plus derivation binding |
| Why is the declared-cutoff candidate search closed? | adversarial plan, candidate ledgers, and freeze report |

The denominator compiler consumes these authorities. It does not redefine
them. In particular, row construction, schema closure, and count agreement are
structural calculations rather than independent evidence of semantic
completeness.

## Denominator input contract

Every feature exposes machine-readable semantic states, scopes, supported
operation identities, variants, manifestations, modifiers, prerequisites, and
typed relations. The acceptance manifest maps all fifteen facets to those
exact selectors. This makes later applicability and obligation rules
explainable without restoring the uniform facet/case expansion.

Operation-only surfaces such as pattern escaping, compiled-pattern
serialization, inspection, and stream lifecycle remain canonical operation
inputs. They do not require duplicate feature identities merely to appear in a
feature-operation cross product.

The denominator compiler must preserve these distinctions:

- `not-applicable`, `no-feature-specific-implication`, and `unresolved` are not
  interchangeable;
- phase is inferred only from structured semantic fields and canonical
  operations;
- a documented complexity guarantee is not an observed timeout;
- security context records source-backed trust, injection, and denial-of-
  service boundaries rather than generic policy prose;
- variant and manifestation facts cannot become canonical invariants; and
- absent applicability evidence cannot be replaced by a generic template.

## Dual authority during rederivation

Semantic authority has advanced to the frozen v4 snapshot. Denominator
authority has deliberately not advanced: the predecessor projection still
contains 12,048 obligation templates and the requirement ledger still contains
9,506 requirements. Their exact byte digests remain locked until the dedicated
rederivation workflow publishes a successor.

Consequently, the current full certification remains non-passing, including
`C4 = 0/9506`. Passing semantic acceptance means that the knowledge inputs and
their machinery are coherent; it does not certify production coverage.

Historical snapshots and research products remain immutable and resolvable.
Newly discovered post-cutoff semantics require a versioned successor snapshot,
renewed candidate disposition, and a new acceptance reference rather than an
in-place rewrite.
