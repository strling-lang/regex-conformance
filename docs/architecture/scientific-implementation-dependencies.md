# Scientific implementation dependencies

This document records the repository-facing dependency architecture for
finishing the Regex Conformance data project. It explains why the work must be
performed in this order without becoming a second operational tracker. Live
status, assignments, approvals, and owner decisions remain in the canonical
program workspace.

## Rebaseline boundary

The declared-cutoff semantic snapshot remains the immutable pre-redesign
baseline. It contains 251 features at digest
`350bfea4c3da07b3426d885aa8ff645ac55539bbb1294a2ea35dd5319541d6c7`.
Its projection contains 12,048 obligation templates, of which 9,506 currently
produce minimum vector requirements. Those counts are preserved facts about
the existing snapshot, not the final scientific denominator. The current
projection is dominated by a uniform facet expansion and many feature fields
still need source-bound, feature-specific semantics.

Broad production-vector authoring, production profile realization, production
execution, and final sustained qualification therefore wait for the scientific
foundations below. Existing qualification results and evidence contracts remain
valid historical engineering evidence; the rebaseline changes their place in
the dependency chain rather than rewriting them.

## Architecture retained by the rebaseline

The following established contracts remain foundational:

- execution profiles are exact component graphs rather than engine labels;
- observations preserve the runtime's native index unit;
- missing values carry explicit absence reasons;
- infrastructure and target faults are attributed separately and fail closed;
- logical executions, retryable physical attempts, and observations are
  distinct identities;
- canonical identities use the repository's assigned, content-derived,
  external, and operational identity modes as appropriate;
- physical attempts and published evidence are append-only;
- checkpoint and recovery chains preserve exactly-once logical completion;
- complete semantic universes are joined to evidence with missing evidence
  retained explicitly;
- published evidence objects are content addressed; and
- Evidence Pack v3 retains its global, factorized, anomaly-complete design.

Behavioral fingerprints may establish empirical equivalence classes for
analysis, execution planning, and storage forecasts. They do not silently merge
component-graph identities, change applicability, or erase historically
identified profiles. Likewise, stable opaque identifiers must be frozen for
scientific entities without replacing content-derived vector and coordinate
identity where that stronger existing contract applies.

## Ordered dependency architecture

### Freeze identities and certification predicates

Immutable scientific identity and migration rules are now frozen. The existing
typed identity architecture remains authoritative; the accepted 22,359-entity
foundation baseline has permanent bindings, while vector revisions and applicability
coordinates retain content-derived identity. See
[Scientific identity and migration contract](scientific-identities.md).

Generated assertions are now bound to a common derivation model so measured,
calculated, researched, external, inferred, constructed, and policy-defined
statements cannot silently substitute for one another. In particular, uniform
facet expansion and legacy fixed audit prose prove structural construction,
not independent semantic completeness. See
[Generated assertion derivation contract](generated-assertion-derivations.md).

Physical attempts now expose digest-bound reset, retry, environment,
checkpoint, resource-budget, fault-attribution, and terminal-outcome
provenance. Terminal observations bind their producing attempt and ordered
attempt set, retries cannot launder away terminal evidence, and repeat
measurements preserve result-signature agreement without premature flakiness
adjudication. See
[Physical-attempt and terminal-outcome provenance](execution-provenance.md).

Certification conditions are now versioned machine-readable predicates over
freshly recomputed repository and evidence state. The evaluator binds exact
input artifacts and derivation revisions, evaluates C1-C7 independently as
`PASS`, `FAIL`, or `BLOCKED`, and requires the full conjunction for final
certification. Supersession and revocation advance through a separate
append-only authority index without rewriting historical reports. See the
[certification contract](../../certification/README.md).

The four foundations now pass their focused integration acceptance. The
[scientific foundation manifest and acceptance report](scientific-foundation.md)
bind their exact digests, non-overlapping authority matrix, cross-contract
adversarial cases, immutable-history rules, and semantic-migration simulations.
This acceptance remains distinct from full data certification, which is still
non-passing. The next dependency is researched semantic reconstruction.

### Complete the semantic knowledge architecture

The existing 251 features now have a content-addressed successor snapshot with
feature-specific, source-bound semantics and explicit knowledge states. All
feature, variant, and manifestation identities were retained, while the
accepted pre-redesign obligation and requirement artifacts remain unchanged.
See [Researched feature semantics](researched-feature-semantics.md).

The architecture omission review has now dispositioned 73 candidates and
published a successor with 268 features, 93 variants, 324 manifestations, 33
operations, 15 semantic facets, and 59 source identities. Phase, documented
complexity guarantees, and security/trust context are structured dimensions;
vendor spellings remain manifestations or profile facts. See
[Semantic architecture dispositions](semantic-architecture-dispositions.md).

The next dependency is a separate adversarial exhaustion review that challenges
the candidate search itself and freezes the final semantic cutoff. The
predecessor 12,048 obligations and 9,506 requirements remain unchanged until
that review closes.

### Derive the true obligation denominator

Emit obligations from feature-specific semantic applicability instead of a
uniform template product. Every emitted obligation must explain the semantic
facts and rules that caused it to exist. Only then regenerate the requirement
snapshot and lower, expected, and conservative denominator forecasts.

### Establish oracle, applicability, and adjudication contracts

Define an oracle hierarchy with circularity guards; implement a total,
proof-bearing applicability evaluator; and formalize the coordinate-state
algebra. Define divergence, waiver, dispute, and unresolved states without
allowing observations to redefine applicability. Claims must follow an
explicit observation-to-adjudication-to-claim process and carry reproducibility
and evidence-confidence metadata. Any proposal for a waiver or
flaky-conformant state to satisfy certification requires explicit program-owner
approval.

### Build the declarative production-vector system

Author canonical exemplars and declarative expansion axes, then produce vectors
with deterministic generators. Include Unicode-data-derived cases, bounded
exhaustion where finite domains permit it, metamorphic relations, and explicit
positive and negative requirements. Adequacy and mutation analysis must close
before the corpus can become the production vector authority.

### Freeze the empirical profile universe

Expand candidate discovery, build a discriminator corpus, fingerprint candidate
profiles, and record evidence-backed equivalence classes. Replace planning
multipliers with an exact profile registry and disposition each executable,
historical, or unreproducible candidate. Empirical similarity may refine work
sharing, but changing identity or certification denominators on that basis is a
separate program-owner decision.

### Finalize evidence and storage architecture

Benchmark family-reference delta encoding without presuming its adoption.
Separate compression-block policy from publication-shard boundaries, normalize
diagnostics, and specify physical-attempt and performance sampling. Complete
the compact query and bitmap/index tier, then validate capacity with realistic
production distinctness and the revised denominator.

The active retained-storage policy is an 8,000,000,000-byte soft stop and a
10,000,000,000-byte hard ceiling, with no paid capacity without explicit
authorization. The complete retained architecture must fit below the hard
ceiling. A larger free archival tier is not part of the active architecture and
would require a separate program-owner decision.

### Qualify the final production architecture

Run focused verification, a representative million-scale exercise, and a
medium rehearsal before the final 48-hour sustained qualification. That final
qualification must exercise the evidence and execution architecture actually
used by production; the unfinished replacement qualification for the earlier
architecture is deferred until this point.

The 48-hour run must coexist with ordinary interactive use of the program
owner's computer, including browsing, editing, communication, normal
development interaction, and lightweight applications. Its preflight measures
material host contention and excludes competing sustained workloads such as
multi-hour campaigns, continuous compiler or build loops, benchmarks, stress
tests, heavyweight background analysis, and resource-intensive unrelated
Docker or virtual-machine work. It must not require zero other processes or a
completely unused device. If measurements demonstrate that stricter isolation
is scientifically necessary, stop for a program-owner decision.

### Realize environments and adapters

Build and qualify every empirically required executable profile only after the
profile registry and production contracts are frozen. Preserve historical
dispositions for profiles that cannot be reproduced rather than removing them
from accounting.

### Execute the complete Coverage Shard campaign

Freeze required coordinates, execute every applicable executable coordinate,
adjudicate and reconcile observations, and pack, verify, checkpoint, and
publish each completed Coverage Shard. Retries may add physical attempts but
never duplicate logical completion.

### Certify the frozen universe and enter maintenance

Regenerate every canonical index from the final frozen inputs, conduct an
adversarial completeness audit, recompute all certification predicates, verify
evidence integrity and storage accounting, and record the exact cutoff and
canonical digests. Successful certification closes the finite construction
project and moves the repository into continuous maintenance.

## Data-project completion contract

At the declared cutoff, the Regex Conformance data project is complete only
when:

1. every system and profile candidate is dispositioned;
2. every semantic candidate is dispositioned;
3. every final semantic requirement is derived and identified;
4. every executable requirement is covered by deterministic vectors;
5. every claim has an admissible oracle or is explicitly
   characterisation-only;
6. every coordinate has an explicit state such as applicable,
   not-applicable, unsupported, untested, or unresolved;
7. every executable profile is realized or explicitly dispositioned as
   historical;
8. every applicable executable coordinate is terminally observed and
   adjudicated;
9. every discrepancy is resolved, waived, permitted, or explicitly unresolved;
10. all required evidence passes integrity certification;
11. all canonical indexes regenerate deterministically;
12. complete retained storage remains below 10,000,000,000 bytes;
13. every certification predicate passes from freshly recomputed state; and
14. the final snapshot records the exact cutoff and canonical digests.

Downstream website consumption is not a completion dependency for this data
project. After certification, new releases, semantic discoveries, and evidence
corrections proceed through the repository's continuous-maintenance contracts.

## Historical qualification disposition

The original 54-checkpoint failed sustained qualification, its valid
interruption and recovery evidence, its 25 percent throughput failure, the
subsequent investigation, preflight and isolation records, native-input
remediation, and the passing medium rehearsal remain preserved. None is
deleted, rewritten, or treated as final production certification. The final
48-hour qualification is deferred until the production evidence and execution
architecture above is ready.
