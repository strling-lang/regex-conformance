## Discovery and identity method

The census started from normative standards, then reconciled feature-rich,
linear/DFA, host-runtime, database, CLI/editor, approximate, multi-pattern, and
historical sources. Secondary catalogs served only as omission detectors.
Primary sources settled semantic claims. The machine ledger includes 49 exact
source identities and 130 source, governed-facility-family, and adversarial
scans.

Candidate conservation separates semantic identity from spelling and context.
Every candidate is dispositioned as a canonical feature or variant, a
manifestation, alias, modifier, host operation, typed interaction, result or
diagnostic facet, historical-only capability, duplicate, non-regex item,
reasoned exclusion, or unresolved item. A source manifestation never allocates
a new feature merely because its syntax differs. A recurring vector never
becomes a composite pseudo-feature merely through co-occurrence.

The independent omission passes attacked engine indexes; POSIX, tagged-DFA,
linear-time, multi-pattern, partial, and streaming behavior; capture/result,
split, iteration, replacement and cursor APIs; and historical, editor, CLI,
database, diagnostics, limits, callout, and embedded-evaluation surfaces. The
passes yielded only represented identities, variants, manifestations,
interactions, non-regex items, and the nine explicitly unresolved legacy
records.

## Obligation compilation

The controlling coordinate is:

```text
profile × feature × semantic obligation × operation
```

Each feature has explicit templates for syntax, core semantics,
search/iteration, captures, Unicode/encoding, options/state, host operation,
replacement, errors, resource/termination, interaction, and differential
behavior. Every template is mandatory, conditional under a machine-evaluable
predicate, informative, or prohibited/not applicable. Unsupported is an
observable applicable result; not applicable suppresses a meaningless
coordinate; unknown stays open.

The exact profile coordinate ledger referenced by the frozen known-universe
census is external and is not present in this repository. The compiler
therefore reports the strongest defensible bounded join, using the census's
1,580/2,170/2,982 current-profile and 11,382/19,318/30,537 historical-profile
bounds and the tracked 77-facility archetype distribution. It does not invent
exact profile identities.

## Vector requirements

The minimum attributable definition set is 9,506 vectors. All 9,506 are
currently missing. The 14 existing qualification vector files contain no exact
semantic projection or obligation references, so they receive no silent reuse
credit; they remain valid operational qualification inputs. The missing set
includes 2,420 negative/error roles, 272 interaction roles, 90 differential
roles, and 1,004 host-operation roles.

One vector definition may carry expectations for multiple operations only when
each obligation and operation-specific outcome is named. Incidental
co-occurrence cannot satisfy another obligation.

## Product readiness and next dependency

The corpus directly supports a Complete Regex Feature Catalog: every feature
has a definition, names, variants, source manifestations, test concepts,
relations, operation implications, Unicode/text behavior, diagnostics, and
provenance. It also supports the Compatibility Explorer contract:

```text
complete canonical feature universe LEFT JOIN empirical compatibility evidence
```

Missing evidence remains Unknown/Not Tested.

Before full-suite execution, the exact frozen profile coordinate ledger must be
materialized and provenance-bound, the exact coordinate expansion compiled,
the 9,506 missing attributable vectors authored and certified, and the required
environment/adapter qualification completed. Capacity now passes, but this
research and design task authorizes no feature-complete campaign execution. The
complete campaign remains unexecuted.
