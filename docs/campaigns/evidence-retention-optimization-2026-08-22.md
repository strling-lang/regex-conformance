# Evidence retention capacity optimization

## Outcome

The rejected semantic-evidence-inheritance experiment has no production
surface. Fifteen inheritance-only files were removed, inheritance hunks were
removed from six shared documentation indexes, and one compact research note
preserves the measured negative result. No semantic-corpus file, profile,
feature, obligation, vector requirement, or denominator coordinate was removed.

The restored feature-complete baseline reproduced 14,559,081,529 conservative
bytes. The selected Compact Evidence Pack v3 retention contract projects
7,452,076,843 bytes. It saves 7,107,004,686 bytes (48.814924704%) and leaves
547,923,157 bytes below the 8 GB operational soft stop and 2,547,923,157 bytes
below the 10 GB hard cap.

The retention measurement executed no conformance coordinate. It read the
completed million-qualification Evidence Pack v2 staging corpus and built a
disposable v3 representation in memory twice. It performed retained-block
reconstruction and corruption injection without writing or mutating source
evidence. Any normal post-promotion public-CI vertical validation remains
separate from the feature-complete campaign.

## Preservation tiers

- Tier A protects semantic results, match and capture facts, replacements,
  split/iteration outcomes, compile/native errors, exact identities and
  provenance, attempts/retries, anomaly evidence, and integrity. No Tier A datum
  was removed.
- Tier B covers reducible depth such as performance repetition and routine
  resource sampling. No Tier B reduction was needed.
- Tier C covers repeated or lowest-marginal-value operational representation.
  The selected change is confined to this tier.

## Selected retention rule

A process record is summarized only when all of the following are proved:

- outcome is `completed` and exit code is zero;
- native diagnostic is null;
- stderr is exactly empty with its known empty SHA-256;
- canonical and semantic authority flags are false;
- stdout digest and positive byte length are structurally valid; and
- the exact provider plan is retained.

An unknown, absent, malformed, or contradictory field fails closed and retains
the full record. Errors, timeouts, signals, nonzero exits, stderr, native
diagnostics, truncation, redaction, containment/resource events, and anomalies
can never qualify.

For a qualifying record, v3 retains the provider plan and a routine-success
marker. Constant fields reconstruct exactly. The per-process stdout digest and
byte count are intentionally omitted operational telemetry; if canonical stdout
is independently regenerated, those fields can be restored and verified. One
ordered length-prefixed RFC 8785/SHA-256 commitment covers all 42,473 summarized
records, along with their count and aggregate stdout bytes. The commitment and
larger manifest are included in the measured final footprint.

## Information no longer physically retained

For routine clean process successes only:

- the directly stored per-process stdout SHA-256;
- the directly stored per-process stdout byte count; and
- repeated copies of completed outcome, exit code zero, null diagnostic, empty
  stderr digest/count, and false authority flags.

The constant fields remain deterministically reconstructible. A single routine
process digest is no longer directly queryable; independently regenerating the
stdout stream restores it, and the whole ordered set is commitment-verifiable.
Random legacy observation and attempt labels and hypothetical v2 container
identity remain omitted under the already accepted v3 contract. Existing v2
evidence is unchanged.

## Downstream sufficiency

STRling retains exact feature support, lowering-relevant semantics, errors,
profile/backend differences, portability evidence, and historical compatibility
scope. The Compatibility Explorer can still distinguish Supported,
Unsupported, Partial/conditional, N/A, Unknown/not tested, and
Inconclusive/conflicting. Missing ancillary routine telemetry cannot be confused
with missing compatibility evidence because the retained contract explicitly
marks the process as a summarized clean success.

## Execution dependency

Capacity is no longer the blocker. Before a separately authorized full suite,
the exact frozen profile ledger must be materialized and provenance-bound, the
exact coordinate expansion must be compiled, all 9,506 missing production
vectors must be authored and certified, and required environments/adapters must
qualify. This task grants no feature-complete execution or publication
authority.
